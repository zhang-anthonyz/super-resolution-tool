# 图片/视频超分工具 — 完整技术方案

> 版本 v1.2 · 2026-10-10 · 目标平台：Windows 10/11 桌面（含独立显卡）
> 定位：本地离线运行、无需联网、跨 NVIDIA / AMD / Intel 三厂商 GPU 的图片+视频超分辨率工具

---

## 一、需求分析

### 1.1 需求拆解

| # | 原始需求 | 归类 | 关键隐含约束 |
|---|---------|------|-------------|
| 1 | 运行前检查环境，必须检测到独立显卡 | 前置校验 | 准确区分「独显」与「核显」；AMD/Intel 核显不能误判 |
| 2 | 完美兼容 NVIDIA / AMD / Intel 三厂 | 核心难点 | NVIDIA→CUDA；**AMD→DirectML + Vulkan 双后端（UI 可选）**；Intel→DirectML/OpenVINO |
| 3 | 附带 Python 环境 | 打包分发 | 解释器+依赖+模型打包，开箱即用 |
| 4 | 图片超分：单张+批量；jpg/png/webp；选模型、自定义倍数、自定义导入 | 图片管线 | 任意倍率→scale-aware 模型；自定义模型标准化 |
| 5 | 视频超分：仅单条；解码→逐帧超分→合成；最大化 ffmpeg 兼容 | 视频管线 | 编码器按厂商路由；**仅支持 8bit SDR，10bit/HDR 不支持（UI 提示）** |
| 6 | UI 简洁高效、不撞色、提示/报错完善 | 交互质量 | 异步、进度/取消/日志/错误分级；含后端选择器、场景选择器 |
| 7 | 先分析 → 选型 → 完整方案 | 本交付物 | 本文档 |

### 1.2 关键技术纠正（决定架构走向）

| 设想/事实 | 实际情况 | 对方案的影响 |
|----------|---------|-------------|
| **AMF** | 是**视频编解码硬件加速**（对标 NVENC/QSV），**不是推理后端**，跑不了超分模型 | AMF 用于**视频编码环节**（`h264_amf`/`hevc_amf`） |
| **ROCm** | 官方**仅支持 Linux**，Windows 版已废弃 | AMD 在 Windows 不能用 ROCm 推理 |
| **Vulkan** | 跨厂商图形/计算 API，NVIDIA/AMD/Intel 均支持 | AMD 的**第二推理后端**（ncnn / Anime4KCPP） |
| **DirectML** | DX12 之上的跨厂商推理 API | AMD/Intel 的**主力推理后端** |

**结论**：Windows 上 AMD 的推理后端 = **DirectML（DX12）+ Vulkan 双选**，由用户在界面上切换；NVIDIA 走 CUDA/TensorRT；Intel 走 DirectML/OpenVINO。

### 1.3 非功能性需求

- **性能**：视频逐帧 GPU 推理 + 硬件编码；大图分块（tile）防显存溢出。
- **健壮性**：显存不足自动降级、异常可恢复、报错可定位（环境/模型/文件/编码四类）。
- **可移植性**：打包产物在无 Python、无 ffmpeg 的机器上直接运行。
- **离线**：模型首次联网下载后缓存，之后完全离线。

## 二、关键技术选型

### 2.1 核心决策：SR 推理引擎（方案 A，已确认）

| 显卡厂商 | 推理后端 | 默认 | 说明 |
|---------|---------|------|------|
| NVIDIA | CUDAExecutionProvider / TensorRT | CUDA | 最佳性能，全功能 |
| NVIDIA | DirectML | 备选 | 跨厂商统一路径 |
| **AMD** | **DmlExecutionProvider（DirectML/DX12）** | **推荐** | ONNX 生态统一、稳定 |
| **AMD** | **Vulkan（ncnn / Anime4KCPP）** | **可选** | 性能更优、Anime4K 专用；实验性 |
| Intel | DmlExecutionProvider / OpenVINO | DirectML | Arc 独显；OpenVINO 更优 |
| 兜底 | CPUExecutionProvider | 仅异常降级 | 需求要求有独显，故仅作容错 |

- **优点**：ONNX 是事实标准，Real-ESRGAN/ESRGAN/SwinIR 均可导出，自定义模型导入只需「ONNX + 元数据」；任意倍率由 SRMD 支撑。
- **缺点**：`onnxruntime-gpu`（CUDA）与 `onnxruntime-directml`（DML）互斥，需处理双运行时加载（见 4.2）。

### 2.2 后端选择器（Backend Selector）

UI 上按「厂商检测结果」动态呈现可选后端，用户可切换：

- NVIDIA：`CUDA（推荐）` / `DirectML`
- AMD：`DirectML（推荐）` / `Vulkan（实验性）`
- Intel：`DirectML（推荐）` / `OpenVINO`（可选）
- 所有厂商：`CPU`（兜底，灰色标注「慢」）

后端切换即时生效，模型列表随之后端能力联动（如 Anime4K 仅在 Vulkan/CPU 下可用，见 2.4）。

### 2.3 其余技术栈

| 类别 | 选型 | 版本建议 | 理由 |
|------|------|---------|------|
| 语言 | Python | 3.11 | ONNX Runtime / PySide6 / PyInstaller 兼容性最佳 |
| GUI | PySide6（Qt6） | 6.x | LGPL 可商用、原生观感、成熟异步 |
| 图像 I/O | Pillow + NumPy | — | 原生 jpg/png/webp；NumPy 作张量载体 |
| 视频编解码 | ffmpeg（gyan.dev **full** 静态包） | 6.x/7.x | 含 NVENC/AMF/QSV 三厂硬编 + libx264/265 软编兜底 |
| ONNX 推理 | onnxruntime-gpu / onnxruntime-directml | 1.17+ | 方案 A 双后端 |
| Vulkan 推理 | realesrgan-ncnn-vulkan（ncnn）+ Anime4KCPP | 见 2.4 | AMD 第二后端 |
| NVIDIA 信息 | nvidia-ml-py (pynvml) | — | 精确读显存/驱动 |
| 硬件枚举 | DXGI（ctypes）+ WMI | — | 跨厂商精确读显存（WMI AdapterRAM 有 4GB 截断） |
| 打包 | PyInstaller | 6.x | one-dir，规避杀软误报与解压慢 |

### 2.4 模型与场景预设（Scene Profile）

**场景预设**：用户选择「真实 / 2D 动漫 / 3D·CG」三类场景，系统自动映射默认模型与推荐参数，仍可手动改模型。

| 场景 | 适用内容 | 默认模型（ONNX） | 可选算法 |
|------|---------|-----------------|---------|
| **真实** | 照片、实拍视频、人像、风景 | RealESRGAN_x4plus | general-x4v3、x2plus |
| **2D 动漫** | 动漫、漫画、插画、动画视频 | RealESRGAN_x4plus_anime_6B | **Anime4K**、animevideov3 |
| **3D·CG** | 游戏画面、3D 渲染、CG 截图 | realesr-general-x4v3（通用，暂无专用模型） | 自定义导入 |

**ONNX 模型清单**（走 CUDA / DirectML 后端）：

| 模型 | 倍率 | 适用 |
|------|------|------|
| RealESRGAN_x4plus | 4x | 真实·通用（默认主力） |
| RealESRGAN_x2plus | 2x | 真实·2 倍原生 |
| RealESRGAN_x4plus_anime_6B | 4x | 2D 动漫 |
| realesr-general-x4v3 | 4x | 通用+降噪（denoise 输入），3D/CG 默认 |
| realesr-animevideov3 | 4x | 动漫视频（去闪烁友好） |
| **SRMD_x4** | **2/3/4x 任意** | 任意倍率（scale 作为输入） |

**Anime4K（2D 专用算法，非 ONNX）**：

- Anime4K 是 bloc97 的开源动漫超分算法，**不是 ONNX 模型**，无法塞进 ONNX Runtime，需独立集成。
- 集成方式采用 **Anime4KCPP**（TianZerL，Anime4K 的高性能 C++ 实现），支持 CPU / CUDA / **Vulkan** / OpenCL 后端，提供 CLI。
- 在本工具中：Anime4K 仅在「2D 动漫」场景下可选，后端走 **Vulkan（Anime4KCPP Vulkan 模式）** 或 CPU。
- 与 Vulkan 后端天然呼应：AMD 用户选 Vulkan 后端时，2D 场景可用 Anime4K + ncnn 的 Real-ESRGAN。

**自定义倍率实现**：优先 SRMD（scale 输入，2/3/4x）；非整数/超范围倍率用「超分到 ≥ 目标再 Lanczos 回缩」，并提示用户为插值回缩。

**自定义导入模型**：ONNX + 元数据清单（见 4.4）。

### 数据流

- **图片**：文件 → Pillow 解码 → 分块 → 推理（ONNX 或 Vulkan）→ 拼接 → 编码写出。
- **视频**：ffmpeg 解码 `rawvideo/rgb24` → NumPy 逐帧 → 推理 → ffmpeg 编码（按厂商硬编）→ 音频 remux。

## 四、关键子系统设计

### 4.1 环境检测模块（EnvironmentChecker）

启动主窗口前执行：

| 检测项 | 方法 | 判定 |
|--------|------|------|
| 独立显卡存在性 | DXGI 枚举适配器，读 `DedicatedVideoMemory` | > 0 判定独显；全 0 → 拦截提示 |
| 显卡厂商 | DXGI `VendorId`（0x10DE=N, 0x1002=AMD, 0x8086=Intel） | 决定后端路由 |
| 显存容量 | DXGI `DedicatedVideoMemory`（精确）；NVIDIA 用 pynvml 复核 | <4GB 警告、<2GB 建议降 tile/倍率 |
| 后端可用性 | NVIDIA→pynvml 驱动；AMD→`get_available_providers()` 含 DML；Vulkan→检测 Vulkan 驱动/ncnn 可执行 | 后端不可用→明确报错并禁用对应选项 |
| 资源完整性 | ffmpeg/ffprobe、ncnn、Anime4KCPP、至少一个模型 | 缺失→引导下载/定位 |

**独显 vs 核显**：Intel 有核显（UHD/Iris）也有独显（Arc），不能按「Intel=核显」一刀切，靠 `DedicatedVideoMemory` + 型号名（Arc/Iris Xe MAX）区分；AMD APU 核显同理。

### 4.2 SR 推理引擎（多后端 + 双运行时）

**BackendSelector**：依据 4.1 结果 + 用户 UI 选择，实例化对应后端，统一暴露 `SuperResEngine` 接口（`upscale_image` / `upscale_batch` / 进度/取消回调）。

**双 onnxruntime 共存解法**：两个 wheel 分别解包到 `runtime/cuda/` 与 `runtime/dml/`，运行时按后端用 `importlib` + `sys.path` 动态加载，共享上层接口。

**三个后端实现**：

| 后端 | 实现 | 要点 |
|------|------|------|
| ONNX·CUDA | onnxruntime-gpu | CUDA/TensorRT EP，默认 fp16（失败回退 fp32） |
| ONNX·DirectML | onnxruntime-directml | DML EP，默认 fp32（AMD 的 DML fp16 支持参差） |
| Vulkan | realesrgan-ncnn-vulkan（ncnn）+ Anime4KCPP | 见下 |

**Vulkan 后端集成方式**（诚实说明工程代价）：

- Real-ESRGAN 系列 → `realesrgan-ncnn-vulkan`（ncnn，官方已提供转换好的 .param/.bin 模型）。
- Anime4K → `Anime4KCPP`（Vulkan 模式）。
- **V1 采用 subprocess 调 CLI**（成熟、开箱即用、Windows 有官方二进制），代价是进度/取消控制为「文件级/帧级」粗粒度，帧级交互走临时文件；**V2 若需精细控制可编译 ncnn 原生 Python 扩展**（构建维护成本高，暂缓）。

**引擎内部通用要点**：tile 分块（默认 512，显存紧张降 256，带 `tile_pad` 重叠防缝，按「显存余量」自适应）；统一 RGB/CHW/[0,1] 张量契约；推理循环内检查取消标志。

### 4.3 图片管线

- **单张**：选文件 → 选场景/模型/倍率 → 超分 → 另存（覆盖/加后缀）。
- **批量**：多选文件 + 文件夹递归（过滤 jpg/jpeg/png/webp）→ 队列并发（IO 并行、GPU 串行）→ 输出目录 + 命名规则（`原名_x{scale}`）。
- **进度/错误**：每张成功/失败计数、失败原因列表、中途取消与断点跳过。

### 4.4 模型管理（含自定义导入 + Anime4K）

- **内置 ONNX 模型**：首次运行从镜像下载（断点续传 + SHA256 校验），缓存至 `models/onnx/`。
- **Anime4K**：打包 Anime4KCPP 可执行文件，随工具分发（体积小），无需下载模型权重。
- **自定义导入**：`模型名.onnx` + 可选 `模型名.json` 元数据：

```json
{
  "name": "mymodel",
  "scale": 4,
  "input_name": "input",
  "output_name": "output",
  "scale_input": null,
  "denoise_input": null,
  "channel_order": "RGB",
  "normalize": [0, 1],
  "tile_size": 512,
  "description": "自定义超分模型"
}
```

未提供元数据时走「智能探测」（按 ONNX 图输入数量/形状推断 scale 输入），失败要求补全。

### 4.5 视频管线（仅 8bit SDR + 编码器路由）

```
输入视频 → ffmpeg 解码(rawvideo rgb24) → Python 逐帧 NumPy → SR 引擎 → 写回 pipe → ffmpeg 硬编 → 音频 remux
```

- **8bit 限制（本次确认）**：V1 仅支持 8bit SDR。
  - 检测：ffprobe 读 `pix_fmt`（是否含 `10le/12le`）+ `color_primaries/color_transfer`（是否 bt2020/HDR）。
  - **UI 提示**：视频选择区常驻小字提示「当前版本仅支持 8bit SDR 视频，10bit/HDR 暂不支持」；选中 10bit/HDR 视频时弹预警并阻止开始。
- **编码器路由**（**用户可选 H.264 / HEVC，默认 H.264**；按厂商自动匹配硬编码器，失败回退软编）：

| 厂商 | H.264 | HEVC |
|------|-------|------|
| NVIDIA | h264_nvenc | hevc_nvenc |
| AMD | h264_amf | hevc_amf |
| Intel | h264_qsv | hevc_qsv |
| 兜底 | libx264 | libx265 |

- **关键技术点**：帧走管道（pipe）避免海量临时文件（可选「落盘帧缓存+断点续跑」供超大视频）；保留原帧率/分辨率/SAR；音频 `-c:a copy` 原样 remux 避免音画不同步；进度按「已处理帧/总帧数」（ffprobe 取总帧）+ ETA。

### 4.6 UI 设计

- **框架**：PySide6 单窗口 + 顶部 Tab（图片超分 / 视频超分 / 模型管理 / 设置）。
- **布局要点**：
  - **场景选择器**：真实 / 2D 动漫 / 3D·CG 三选，选中后自动填入默认模型（可改）。
  - **后端选择器**：按厂商显示可选后端（AMD 显示 DirectML/Vulkan），即时生效。
  - **视频区**：8bit/HDR 常驻提示。
- **配色**：单一主色 + 一个品牌色点缀（深色为主）；语义色（成功绿/警告橙/错误红）仅用于状态提示，不做大面积装饰。
- **异步**：所有任务跑 QThread，信号更新进度/日志；取消随时可用。
- **报错分级**：环境问题→启动拦截弹窗；参数/文件问题→内联提示；运行时错误→日志面板分级（Info/Warning/Error + 时间戳 + 可读原因 + 一键复制）。

## 六、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| DirectML 在 AMD 性能不如 CUDA/Vulkan | AMD 吞吐偏低 | **已提供 Vulkan 后端可选**；默认 DirectML 保稳定，用户可切 Vulkan 提速 |
| Vulkan 后端（ncnv/Anime4KCPP）为 CLI 集成，进度控制粗 | 取消/进度粒度降级 | V1 接受文件/帧级粒度；V2 编译原生扩展补精细控制 |
| AMD 驱动对 Vulkan shader 兼容性偶发问题 | Vulkan 后端个别驱动失败 | 后端切换即可回退 DirectML；报错明确指向后端 |
| 双 onnxruntime 动态加载失败 | 特定机器无法推理 | 构建期充分测试；提供「运行时自检」诊断页 |
| Intel Arc 驱动成熟度 | 部分 Arc 上 DML/OpenVINO 异常 | Arc 优先 OpenVINO；异常回退 CPU 并明确提示 |
| 10bit/HDR 视频 | V1 不支持 | 明确声明 + UI 提示 + 选择时预警；V2 规划 tone-mapping |
| 3D/CG 暂无专用模型 | 3D 场景用通用模型效果一般 | 默认 general-x4v3；开放自定义导入 |
| 显存不足（低端独显） | 大图/视频 OOM | 自适应 tile 下调 + 显存预算监控 + 友好报错 |
| 自定义模型格式不兼容 | 导入失败 | 元数据契约 + 智能探测 + 明确报错，不静默失败 |

## 七、里程碑规划（建议 Wave 拆分）

| Wave | 内容 | 验证标准 |
|------|------|---------|
| W1 环境检测 | DXGI/WMI/pynvml 枚举 + 独显判定 + 后端路由 + 8bit 检测 | 三厂真机正确识别厂商/显存/后端 |
| W2 SR 引擎·ONNX | 双后端 + tile + fp16/fp32 + 场景/模型加载 | 单张图片在 NVIDIA CUDA / AMD DirectML 上出正确结果 |
